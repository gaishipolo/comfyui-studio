# 用户隔离（任务/素材）+ 手动共享 — 设计文档

> 日期：2026-10-29
> 状态：已实现
> 起因：用户反馈「生成的会话任务、任务、素材库都没做用户隔离，角色功能没作用」

## 1. 背景

角色（admin/member）此前只管两件事：用户管理页可见性、删除归属校验。
**读取链路完全放开** —— 任务列表、素材列表、单条详情、下载、打标签，
任何登录用户都能看到、拿到全员的数据。角色形同虚设。

## 2. 产品拍板：默认隔离 + 手动共享

核心分岔是素材库的性质：个人产出还是团队产出。选定**混合**：

- **任务**：各看各的（生成记录是个人工作流），admin 可见全部（带创建人列）
- **素材**：默认归生成者；可手动「共享给团队」，共享后全员**可见可下载**
- **共享 ≠ 共同所有**：打标签、删除、共享开关仍是作者或管理员的权利。
  共享的是「看」的权限，不是资产的控制权 —— 否则共享一张图就等于送人了

## 3. 规则表

| 操作 | 本人 | 队友（未共享） | 队友（已共享） | admin |
|---|---|---|---|---|
| 任务列表/详情 | ✔ | ✘ | — | ✔ 全部 |
| 任务取消/重试/删除 | ✔ | ✘ 403 | — | ✔ |
| 素材列表/详情/下载 | ✔ | ✘ | ✔ | ✔ 全部 |
| 素材打标签/删除/共享开关 | ✔ | ✘ 403 | ✘ 403 | ✔ |
| 素材选作生成输入 | ✔ | ✘ 404 | ✔ | ✔ |
| 标签云 / 批量下载 | 自己的 | 剔除 | 含共享的 | 全部 |

**错误语义**：读接口越权报 **404**（不泄露「存在但无权」）；
写接口越权报 **403**（保留「只能操作自己提交的」文案风格）。
素材当输入的越权报「素材不存在」，与详情 404 同语义。

## 4. 实现

- **规则唯一出处 `app/access.py`**：`can_view_task` / `can_modify_task` /
  `can_view_asset` / `can_modify_asset` + 归属查询助手（`task_owner_map` /
  `creator_display_names`，显式 select，禁懒加载）。三个 API 文件都从这里引，
  测试有守卫盯着，谁内联写权限判断谁就挂。
- **素材归属走 `task.created_by`**（素材表没有归属字段）；`Asset.is_shared`
  新列走 `_COLUMN_MIGRATIONS`（老库启动时自动升），存量数据默认不共享 ——
  存量全是 admin 建的，自动归 admin，无需迁移数据。
- **响应补字段**：`AssetResponse` + `is_shared/created_by/creator_name`，
  `TaskResponse` + `creator_name`（创建人显示名）。顺手修了个洞：
  **retry 原来没有归属校验**，谁都能拿别人失败的任务重跑。
- **`list_assets` 的 join 只做一次**：归属过滤和按场景筛选都要过任务表，
  重复 join 会生成两条 join。`need_join = bool(template_id) or not is_admin`。
- **共享素材的下载走 `/api/tasks/{task_id}/assets/{filename}`**（预览/下载同一路由），
  这条路要按「任务可见 **或** 素材可见」判，只判任务的话共享卡片打不开。
- **前端**：素材详情加归属行 + 共享开关（仅本人/管理员可见），
  别人的共享素材隐藏打标签/删除按钮；卡片角标「共享中 / 来自 X」；
  任务页 admin 多一列「创建人」。

## 5. 验证

`backend/tests/verify_user_isolation.py` 56 项全绿（真实 API 实测）：
任务隔离 11 项、写操作越权 4 项、素材默认隔离 9 项、共享语义 10 项
（含「共享后打标签/删除仍 403」「收回后又看不见」）、标签云/批量下载/输入 6 项、
回归守卫 5 项。20 套后端测试全绿。

## 6. 测试设计教训

**别拿公共测试标签断言「看不见」** —— seed() 给所有素材打了同一个标签，
B 自己的素材也带它，拿它验「B 的标签云不含此标签」必假红。
断言可见性要用**独有**标记（`iso-secret-{uuid}`）。
