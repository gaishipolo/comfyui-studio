# ComfyUI 集成工作台 — 设计文档

> 日期：2026-10-27
> 状态：设计已确认，待实现

## 1. 背景与目标

为内容和运营团队提供一个**无需理解 AI 底层原理**的生成工作台。用户只需选择场景、填写表单、提交任务、获取结果。

**核心诉求：**
- 多模态支持（文生图、人脸参考等，未来可扩展到文生视频、文生文本等）
- 可扩展：工作流模板可配置、生成引擎可切换、前端功能模块可插拔
- 小团队轻量认证（管理员 / 普通用户）

**三层解耦：**
- **前端**：纯展示和交互，模板驱动动态渲染，不写死生成逻辑
- **后端**：任务管理 + 模板 CRUD + 素材存储 + 用户认证
- **引擎层**：统一 `GenerationProvider` 接口，ComfyUI 是第一个实现

**技术栈：**
- 前端：React + Vite + TailwindCSS
- 后端：FastAPI + Celery + PostgreSQL + 对象存储（MinIO / 本地磁盘可切换，见「素材管理」）
- 通信：REST API + WebSocket

## 3. 工作流模板系统

每个 AI 场景 = 一个 JSON 模板，包含三部分：

### 3.1 输入 Schema（前端渲染表单）

```json
{
  "fields": [
    { "name": "prompt", "label": "提示词", "type": "textarea", "required": true },
    { "name": "ref_image", "label": "参考图片", "type": "image_upload", "required": true },
    { "name": "width", "label": "宽度", "type": "select", "options": [512, 768, 1024, 1344], "default": 1024 },
    { "name": "seed", "label": "随机种子", "type": "number", "required": false, "advanced": true }
  ]
}
```

### 3.2 工作流映射（后端注入 ComfyUI JSON）

```json
{
  "engine": "comfyui",
  "workflow_file": "flux2_text_to_image_ref_face.json",
  "param_mapping": {
    "prompt": "76.inputs.value",
    "width": "103.inputs.value",
    "height": "106.inputs.value",
    "ref_image": "112.inputs.image",
    "seed": "99.inputs.noise_seed"
  }
}
```

### 3.3 输出定义

```json
{
  "outputs": [
    { "name": "result_image", "type": "image", "node": "108" }
  ]
}
```

**管理端流程：** 上传 ComfyUI 工作流 JSON → 配置参数映射 → 保存模板 → 用户端立即出现新场景表单。

## 4. 任务队列 + 素材管理

### 任务生命周期

```
提交 → 排队中(pending) → 执行中(running) → 成功(done) / 失败(error)
```

- **批量提交**：一次表单可提交 N 个任务，独立排队、独立出结果
- **WebSocket 推送**：状态变化实时推送（排队 → 开始 → 进度 → 完成）
- **历史保存**：任务记录永久保存，离开页面回来可查看
- **失败处理**：错误信息入库，前端展示原因，支持一键重试

### 素材管理

| 功能 | 说明 |
|------|------|
| 自动入库 | 任务完成 → 结果自动存储到对象存储 + 数据库 |
| 标签 | 自动打场景标签，支持手动加标签 |
| 搜索 | 按标签、时间、创建人、场景筛选 |
| 批量下载 | 勾选多个素材打包下载 ZIP |

**存储后端（已实现）：** `app/filestore.py` 是唯一存取入口，业务代码不直接摸磁盘。
`settings.STORAGE_BACKEND` 切换实现：`local` = 本机目录（默认，`STORAGE_DIR`）、
`minio` = MinIO / S3 兼容对象存储（`MINIO_*` 配置项）。对象键固定用 POSIX 分隔符
（`{task_id}/{文件名}`），与库里的 `assets.file_path` 同构，所以存量数据不需要迁移表结构；
`filestore.safe_key` 读入端同时接受 `/` 与 `\`，兼容历史记录。

下载走**后端代理转发**而非预签名直连 —— 现有前端 `fetchAssetBlob` 带 JWT 取文件的
鉴权链路不变。本地后端用 `FileResponse`（支持 HTTP Range，视频拖进度条不卡），
对象存储后端退回流式转发。若日后要省后端带宽，再在此处加预签名分支即可。
| 详情 | 查看生成参数，支持复制参数重新生成 |

### 数据库表

| 表 | 用途 |
|----|------|
| `templates` | 场景模板（JSON Schema + 工作流映射） |
| `tasks` | 生成任务（状态、参数、结果引用） |
| `assets` | 生成素材（文件路径、标签、关联任务） |
| `users` | 用户（角色：admin / member） |

## 5. 错误处理

| 场景 | 处理方式 |
|------|----------|
| ComfyUI 不可用 | 健康检查 + 任务等待队列自动重试 |
| 生成失败 | 捕获错误存库，前端友好展示 + 一键重试 |
| 批量部分失败 | 独立标记，支持单独重试 |
| 网络中断 | WebSocket 断线自动重连 + 状态同步 |

## 6. 可扩展性设计

1. **新增 AI 场景** → 不改代码。管理员上传工作流 JSON + 配置映射 → 发布
2. **新增生成引擎** → 实现 `GenerationProvider` 接口，注册到引擎工厂
3. **前端功能模块** → 插件化。生成工作台、素材库、审批、看板均为独立模块
4. **多节点扩展** → Celery 任务队列天然支持多 Worker

```python
class GenerationProvider(ABC):
    async def submit(self, workflow: dict, params: dict) -> str
    async def get_status(self, task_id: str) -> TaskStatus
    async def get_result(self, task_id: str) -> list[Asset]
```

## 7. 实施路线（模块分开实现）

按模块独立开发、独立交付：

| 阶段 | 模块 | 内容 |
|------|------|------|
| M1 | **后端基础 + ComfyUI Provider** | FastAPI 骨架、ComfyUI 对接、任务队列、模板 CRUD |
